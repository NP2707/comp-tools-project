Same template, same purpose?

Sometimes. Shared text can encode a substantive workflow, a generic checklist, or a wrapper that delegates work elsewhere. The sample contains all three.

Check the tasks, not just their cluster IDs

Selected pairs in 7 of 14 crossing families still describe the same core task. Examples include spreadsheet editing, Context7 documentation lookup, Azure messaging and GitHub issue management. Language, metadata and runtime variants can split one task across clusters.

Within-cluster controls reveal the reverse: Redis and Unleash share an integration mechanism but target different services. A shared production scaffold also links civic-plan evaluation with accessibility-journal maintenance inside one broad cluster.

Method and limits

The audit recomputed exact five-word-shingle Jaccard for all 649 existing edges and checked content hashes. It includes all 14 cross-cluster families, 20 randomly selected within-cluster controls (seed 20261028), and the three largest controls; overlap leaves 36 families. Pair selection favors crossing pairs and then highest similarity. This is a targeted review, not a population survey.

Title-free equality uses YAML and first-H1 removal, Unicode NFKC, case folding and whitespace collapse. It is a text heuristic, not an execution test. Referenced resources were not evaluated. All 11,015 eligible contents come from the pinned GitHub sample; the full Zenodo corpus was not analyzed.

What this supports

Study task-specific instruction reuse versus generic scaffold reuse. Use independent action/object/domain/output annotations, include within-cluster controls, and evaluate by family and repository. Runtime success needs a separate controlled study.
